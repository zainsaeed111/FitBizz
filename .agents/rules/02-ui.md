# 02 — UI & UX Principles

1. **World-Class International SaaS Aesthetic**:
   - FitBizz visual language communicates: *Professional, Premium, Modern, Trustworthy, Fast, Business-Focused, Clean*.
   - Avoid generic gym clichés: NO dumbbell imagery, NO bodybuilding tropes, NO neon colors, NO heavy glassmorphism, NO noisy gradients, and NO unneeded 3D decorations.

2. **Design System First**:
   - Centralize all colors, typography, spacing, border radii, shadows, icon sizes, and component dimensions in `docs/DESIGN_SYSTEM.md`.
   - Never hardcode arbitrary visual values (e.g. `Color(0xFF2563EB)`) directly inside screen files.

3. **MANDATORY CROSS-PLATFORM UI VERIFICATION (DEFAULT BEHAVIOR)**:
   - **Proactive AI Ownership**: Treat EVERY UI task as `DESKTOP + MOBILE + RESPONSIVE` by default. Neither platform is secondary. Never wait for the user to ask "check mobile" or "check desktop".
   - **Real Responsive Design (Layout Adaptation, Not Shrinking)**:
     - Do NOT simply shrink font sizes, reduce padding, force `Row`s into narrow screens, or hide content.
     - Adapt the layout strategy cleanly based on available width:
       - **Desktop (`>1024px`)**: Permanent side navigation, multi-column dashboard grid, dense data tables, horizontal forms, modal dialogs, mouse hover & keyboard shortcuts.
       - **Tablet (`600px - 1024px`)**: 2-column adaptive grid, collapsible navigation rail/drawer.
       - **Mobile (`<600px`)**: Compact header, bottom navigation, single-column stacked forms, card representations for tables, full-width dialogs or bottom sheets, touch targets >= 48px.
   - **Adaptive Component Rules**:
     - Overlays, Snackbars, Dialogs, Tables, Cards, Modals, and Popups MUST adapt sensibly. A dialog or table that works on desktop but overflows on mobile is INCOMPLETE. A card that looks good on mobile but leaves excessive whitespace on desktop is INCOMPLETE.
   - **No Random Responsive Hacks**:
     - Never fix layout issues with fixed pixel widths, negative margins, magic numbers, or screen-size hacks.
     - Use structural layout strategies: constraints, `Expanded`/`Flexible`, `Wrap`, `LayoutBuilder`, `MediaQuery` breakpoints, and proper scrolling controls.

4. **Component-First Architecture**:
   - Search for an existing component before creating a new UI element.
   - Standardize on reusable primitives: `AppButton`, `AppTextField`, `AppCard`, `AppDialog`, `AppBadge`, `AppDataTable`, `AppBottomSheet`, `AppEmptyState`, `AppErrorState`, `AppLoadingState`, `AppStatCard`.

5. **Completion Check (Desktop + Mobile Verified)**:
   - Before declaring any UI task complete, internally verify:
     - [ ] Desktop layout verified
     - [ ] Mobile layout verified
     - [ ] Responsive breakpoint transition verified
     - [ ] Zero `RenderFlex` or horizontal overflows
     - [ ] Zero clipped text/buttons or broken overlays/dialogs
     - [ ] Touch targets >= 48px on mobile; keyboard/mouse interactions ready on desktop
     - [ ] Explicitly state what was executed/verified and what could not be run.
